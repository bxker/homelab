Careful with this one: the plain `disable: [traefik, servicelb]` + restart from this issue would have deleted every Traefik CRD on the running cluster, and with them every IngressRoute and Middleware. I reproduced that on a throwaway k3s v1.36.5. The PR runs a lab-tested sequence instead. It drops k3s's `traefik-crd` release record first so the CRDs survive, then restarts, strips ServiceLB's finalizers, waits for the uninstall, and waits for ArgoCD to restore the `traefik` IngressClass. It applies on your next `mise run k3s-install`, with a ~30 s API restart.
